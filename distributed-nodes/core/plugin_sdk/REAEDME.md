# 实现一个基于 CAF 的插件系统
+ 必须支持热重载
+ 各个插件之间，隔离，尽可通过actor消息通信，不同dll不能之间调用对方的函数
+ dll仅导出生命周期相关接口

如果有一个插件，专门用于管理逻辑配置，那么，别的插件读取配置，也要序列化，并且缓存到调用方插件，然后调用方要monitor配置插件，如果配置插件卸载，则调用插件必须情况配置缓存

# Actor 之间通信的约定
+ 本地Actor通信，也就是同一个插件内，可以传C++对象，shared_ptr,unique_ptr等
+ 插件之间通信，启用远程序列化，必须采用CAF已注册的类型或C接口，其他类型必须序列化。禁止直接传递C++对象。采用CAF序列化或者 Protobuf/FlatBuffers。FlatBuffers 还没做过试验。
+ 可定义插件系统稳定的消息id，用CAF_ADD_TYPE_ID 或 ATOM 显式定义

# 插件生命周期管理
+ 卸载前，确保所有属于该插件的Actor都已销毁
+ 使用 caf::scoped_actor 进行同步等待，确保没有残留消息在队列中
